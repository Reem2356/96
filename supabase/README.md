# إعداد Supabase لمشروع «صوتك يرسم الوطن»

## 1) إنشاء المشروع والجدول

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com).
2. افتح **SQL Editor** ونفّذ محتوى ملف [`schema.sql`](./schema.sql) كاملاً.
3. من **Database → Replication**، فعّل النشر (Realtime) لجدول `submissions`
   حتى تعمل التحديثات الحية في صفحتي `/mosaic` و `/display`.

## 2) متغيرات البيئة (Frontend)

انسخ `.env.example` إلى `.env.local` واملأ القيم من **Project Settings → API**:

```
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi... # مفتاح anon العام فقط
```

⚠️ **لا تضع مطلقًا `service_role key` في هذا الملف أو في أي مكان يصل إليه
المتصفح.** هذا المفتاح يتجاوز كل سياسات RLS ويجب أن يبقى فقط في بيئة خادم
موثوقة (مثل Supabase Edge Functions) إن احتجت إليه مستقبلاً.

بدون هذين المتغيرين، يعمل الموقع تلقائيًا بوضع البيانات التجريبية
(localStorage) دون أي إعداد إضافي — مناسب للتطوير والعرض السريع.

## 3) إنشاء حساب مشرف (Admin)

1. من **Authentication → Users**، أنشئ مستخدمًا جديدًا (بريد + كلمة مرور)
   لكل مشرف تريد منحه صلاحية الدخول إلى `/admin`.
2. انسخ الـ `UUID` الخاص بالمستخدم من نفس الصفحة.
3. من **SQL Editor** نفّذ:
   ```sql
   insert into public.admins (user_id) values ('<UUID-المستخدم>');
   ```
4. سجّل الدخول من `/admin` بنفس البريد وكلمة المرور.

بدون Supabase مُهيّأ، تعمل لوحة الإدارة بوضع تجريبي بكلمة مرور بسيطة معرّفة
في `VITE_ADMIN_MOCK_PASSWORD` (افتراضيًا `watan2026`) — **لأغراض التطوير
المحلي فقط، غير آمنة للإنتاج.**

## 4) الصورة المرجعية (خادم الحرمين الشريفين الملك سلمان)

ضع الصورة الرسمية المصرَّح باستخدامها في:

```
public/reference/king-salman.jpg
```

راجع التعليقات في `src/lib/referenceImage.ts` للتفاصيل الكاملة. بدون هذا
الملف، تستخدم اللوحة نمطًا بديلاً تجريبيًا (بورتريه مجرّد) حتى لا يتعطل العرض.

## 5) الأمان — ملخص

- **RLS مفعّل** على جدول `submissions`: تُنشر المشاركات فورًا بحالة
  `approved` بدون مراجعة إشرافية مسبقة (بطلب صاحب الموقع). لوحة الإدارة
  تبقى متاحة لحذف أو رفض (إخفاء) أي مشاركة غير لائقة بعد نشرها، وهذا
  يتطلب مستخدمًا موجودًا في جدول `admins`.
- **Rate limiting**: طبقة أولى في الواجهة (حد أدنى 20 ثانية بين مشاركتين
  من نفس المتصفح، راجع `mockRepository.ts` / يمكن تطبيق نفس المنطق عبر
  Edge Function للتحقق من عنوان IP في وضع الإنتاج — جدول
  `submission_rate_limits` جاهز لهذا الغرض).
- **تنقية النصوص (XSS)**: `sanitizeText()` في `src/lib/sanitize.ts` يزيل
  أي وسوم HTML قبل الحفظ، بالإضافة إلى أن React يرمّز كل نص معروض تلقائيًا.
- **لا تُخزَّن التسجيلات الصوتية** إطلاقًا — فقط النص الناتج بعد التحويل.
